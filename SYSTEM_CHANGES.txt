1. LIVE GOOGLE FIREBASE FIRESTORE & AUTHENTICATION INTEGRATION
--------------------------------------------------------------------------------
- Centralized Key Management (`src/config/keys.ts`):
  * Environment variable fallback hierarchy: `import.meta.env.VITE_FIREBASE_*` -> `localStorage.getItem("FIREBASE_*")` -> Hardcoded production defaults (`omnisync-pothole`).
  * Real-time Firestore initialization in `/src/services/firebase.ts` with project:
    - Project ID: `omnisync-pothole`
    - Auth Domain: `omnisync-pothole.firebaseapp.com`
    - Collection: `complaints`
- Firebase Authentication Modular Service (`/src/services/firebase.ts`):
  * Initialized and exported `auth = getAuth(app)`.
  * `loginWithGoogle()`: Authenticates via `signInWithPopup(auth, GoogleAuthProvider)`.
  * `setupRecaptcha(containerId)`: Initializes invisible `RecaptchaVerifier` on specified DOM containers.
  * `sendPhoneOtp(phoneNumber, appVerifier)`: Triggers SMS verification via `signInWithPhoneNumber(auth, ...)`.
  * `verifyPhoneOtp(confirmationResult, otpCode)`: Confirms SMS OTP code with `confirmationResult.confirm(otpCode)`.
  * `logoutUser()`: Signs out active user sessions via `signOut(auth)`.
  * `onAuthChange(callback)`: Real-time listener for user session changes via `onAuthStateChanged(auth, callback)`.
- Data Model:
  * `id`: Unique grievance identifier (e.g., `W0488610C948211`)
  * `title`: Complaint title / hazard category
  * `category`: Hazard category code
  * `status`: "Registered" | "Assigned" | "In Remediation" | "Resolved"
  * `ward`: Jurisdiction zone (e.g., "Ward 4 - Central Zone")
  * `location`: Address, latitude, longitude, zone
  * `citizenName`: Reporting citizen name
  * `assignedCrew`: Dispatched rapid patcher / ward inspector
  * `createdAt`: Firestore `serverTimestamp()`
  * `priority`: P1_CRITICAL / P2_URGENT / P3_NORMAL
  * `department`: PUBLIC_WORKS / SANITATION / WATER_SUPPLY / ELECTRICITY
  * `riskScore`, `imageUrl`, `proofOfFixUrl`, `officerNotes`, `etaMinutes`, `aiSummary`, `actionDirectives`
- Real-time Listeners & Auto-Sync:
  * Uses Firestore `onSnapshot` with `orderBy("createdAt", "desc")` to ensure instant updates across all citizen and municipal officer screens simultaneously.
  * Submissions write directly to Firestore via `addDoc` / `setDoc`.
  * Officer status changes, crew assignments, and resolution photologs update Firestore documents via `updateDoc`.

2. GEMINI AI VISION & AUTONOMOUS DISPATCH INTEGRATION
--------------------------------------------------------------------------------
- Gemini Vision Model: `models/gemini-2.5-flash`
  * Server endpoint: `POST /api/gemini/analyze-vision` (proxies vision analysis securely, accepts custom header key or server `GEMINI_API_KEY`).
  * Client service: `analyzeHazardWithGeminiVision` in `/src/services/geminiService.ts`.
  * Features: Pavement defect classification, severity scoring (1-100), automated department mapping, crew allocation recommendation, and safety directives.
  * Visual UI: Integrated live diagnostic badge with loading animations on both Desktop and Mobile grievance forms.
- Gemini Autonomous Dispatch Reasoning: `models/gemini-3.7-flash`
  * Server endpoint: `POST /api/gemini/dispatch` (executes chain-of-thought multi-criteria dispatch optimization).
  * Considers priority, spatial proximity, department jurisdiction, vehicle equipment capabilities, and crew shift availability.
