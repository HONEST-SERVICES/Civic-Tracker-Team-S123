1. ZERO HARDCODED MOCKS & 100% REAL FIRESTORE FLOW
--------------------------------------------------------------------------------
- Real-time Database Collections:
  * `complaints`: Scoped queries (`onSnapshot`) with role-based filtering:
    - `CITIZEN`: Filtered to grievances filed by current user (`citizenUid == auth.currentUser.uid` or reporter match).
    - `FIELD_CREW`: Filtered to grievances in crew's assigned ward (`assignedWard == userProfile.assignedWard`).
    - `WARD_OFFICER`: Filtered strictly to complaints in `userProfile.assignedWard`.
    - `SUPER_ADMIN`: Unrestricted apex access across all wards and national municipal jurisdictions.
  * `units`: Live municipal crew and repair vehicle fleet records:
    - Real-time `onSnapshot` tracking of crew location, status (`AVAILABLE`, `EN_ROUTE`, `MAINTENANCE`), equipment, and active assignments.
  * `users`: User profiles with hierarchical RBAC roles: `CITIZEN`, `FIELD_CREW`, `WARD_OFFICER`, `SUPER_ADMIN`.
- Firestore Writes:
  * Citizen Grievance Submission: Creates records with `serverTimestamp()`, AI Vision diagnostics, and geospatial coordinates.
  * Officer Crew Dispatch & Work Order Allocation: Atomic updates to `complaints` and `units`.
  * Status Transitions & Proof-of-Fix: Uploads remediation photo URLs, inspector closure notes, and resolution timestamps.

10. ARCHITECTURAL & SECURITY AUDIT (DATA BOTTLENECKS, AUTH & IMAGE PERSISTENCE)
--------------------------------------------------------------------------------
- Auth Gating & First-Time User Lifecycle:
  * Audit of session states and unauthenticated gating:
    - Root early return in `App.tsx` conditionally halts mounting of municipal desks when `currentUser === null`, forcing the dedicated `SwachhataAuthScreen.tsx` splash portal.
    - Verified `logoutUser()` executes Firebase Auth `signOut(auth)` and resets user profile reference in state.
- Image Upload & Storage Bottleneck Diagnosis:
  * Identified 1MB Firestore document hard limit vulnerability when raw camera base64 strings (>5MB) are attached.
  * Formulated client-side Canvas 2D image compression architecture (max 800px width/height, 0.75 WebP/JPEG quality) to throttle payload sizes to ~60-90KB prior to Gemini Vision & Firestore write operations.
- Location Capture & Places API Bidirectional Synchronization:
  * Traced Autocomplete -> Pin and Pin Drag -> Geocode synchronization vectors.
  * Preserved loop-free updates via discrete event listeners without circular component re-renders.
- Gemini Multimodal Pipeline & Thinking Stream:
  * Verified inlineData base64 ingestion, structured JSON response schema, and interactive UI scanning indicators ("Scanning pavement anomalies & hazard severity...").
  * Confirmed multi-tier fallback architecture (Server API -> Client GenAI SDK -> High-fidelity municipal heuristics).
- Database Write Reliability & Error Visibility:
  * Verified serverTimestamp integration and collection schema alignment across `complaints`, `users`, `units`, and `public_facilities`.
